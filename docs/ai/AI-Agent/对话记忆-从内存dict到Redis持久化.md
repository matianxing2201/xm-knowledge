# 对话记忆：从内存 dict 到 Redis 持久化

最开始对话历史存在进程内存的一个 dict 里，服务重启记忆就丢了。后面移到 Redis，重启不丢、多实例共享、自动过期清理。

## 1. 为什么要有对话记忆

### 大模型天生"记不住"上下文

```
用户：我头疼
AI：  多久了？                             ← 记住了，这是同一轮

用户：三天了
AI：  有没有伴随发烧？                      ← 记住了，因为后端把历史拼进去了

---
用户：我刚才说了什么？                    ← 后端去 Redis 查到历史，拼回去
AI：  你说头疼三天了
```

后端每轮把「用户消息 + AI 回复」都存起来，下次请求时拼上，AI 才能"记得"以前说过什么。

### 三个存储方案的演进

| 方案     | 特点                     | 阶段     |
| -------- | ------------------------ | -------- |
| 无存储   | AI 每轮失忆，无法多轮对话 | 淘汰     |
| **内存 dict** | 简单，重启丢，单实例     | 第一阶段 |
| **Redis**     | 持久化，共享，自动过期   | 当前方案 |

## 2. 第一阶段：内存 dict

最开始是这样：

```python
# 模块级全局变量
sessions: dict[str, list] = {}

def chat_stream(session_id: str, message: str):
    history = sessions.setdefault(session_id, [])
    history.append({"role": "user", "content": message})

    # ... 调模型 ...

    history.append({"role": "assistant", "content": collected_content})
```

### 内存 dict 的问题

```
                                 ┌─────────────┐
             请求 A ───────────→ │             │
             请求 B ───────────→ │  sessions   │  ← 进程内，Python dict
             请求 C ───────────→ │             │
                                 └─────────────┘
                                     │
                             重启服务 ──→ 全部丢失
```

| 问题         | 后果                                                     |
| ------------ | -------------------------------------------------------- |
| 存在进程内存里 | 服务重启、代码重载、部署更新 → 所有对话历史清空           |
| 单实例独占   | 扩容到 2 个进程 / 2 台机器，各自有各自的 dict，互不共享   |
| 只增不删     | session 越来越多，内存占用持续增长，没有清理机制           |

## 3. 第二阶段：Redis

### 架构变化

```
        改之前                                改之后
  ┌──────────────┐                    ┌──────────────┐
  │  Python 进程  │                    │  Python 进程  │
  │  ┌─────────┐ │                    │               │
  │  │ sessions│ │  ← 进程内          │               │      ┌─────────┐
  │  │  dict   │ │                    │  Redis Client ──────→│  Redis  │
  │  └─────────┘ │                    │               │      │ (独立)  │
  └──────────────┘                    └──────────────┘      └─────────┘
   重启 → 丢失                          重启 → 还在      7 天不活跃 → 自动删
```

### 改了什么

| 模块                          | 改动                                     |
| ----------------------------  | ---------------------------------------- |
| `app/config/config.py`        | 新增 6 个 Redis 配置项，从 `.env` 读取    |
| `app/services/mimo_service.py` | 删掉 `sessions` dict，改成 `_get_redis()` 读写 Redis |
| `.env`                        | 新增 `REDIS_HOST` / `REDIS_PORT` / `REDIS_DB` 等 |

**Route 层和其他代码完全不用动**——Service 层把存储细节封装了。

## 4. Redis 数据结构设计

### Key 设计

```
key:   chat:session:{session_id}
       ↑               ↑
       前缀（可配置）   会话 ID（UUID, 前端传回来的）

value: JSON 字符串
       [{"role": "user",    "content": "我头疼"},
        {"role": "assistant","content": "多久了？"},
        {"role": "user",    "content": "三天了"}]      ← 不含 system prompt

TTL:   604800 秒（7 天）
       每次读写都刷新过期时间，活跃会话不会过期
```

### 为什么不含 system prompt

system prompt 是固定的，每次请求都从 `app/prompts/chat.py` 读取拼接，不需要存 Redis。省空间、改 prompt 时已存的历史不受影响。

### Config 配置项

| 环境变量                  | 默认值     | 作用                 |
| ------------------------ | ---------- | -------------------- |
| `REDIS_HOST`             | `127.0.0.1` | Redis 地址           |
| `REDIS_PORT`             | `6379`      | Redis 端口           |
| `REDIS_DB`               | `0`         | 数据库编号           |
| `REDIS_PASSWORD`         | (空)        | 密码，无认证就不填   |
| `REDIS_SESSION_EXPIRE`   | `604800`    | 会话过期时间（秒）   |
| `REDIS_PREFIX`           | `chat:session:` | Key 前缀           |

## 5. 核心代码

### Redis 连接

```python
def _get_redis():
    """创建 Redis 连接，配置从 current_app.config 读取"""
    config = current_app.config
    return redis.Redis(
        host=config.get('REDIS_HOST', '127.0.0.1'),
        port=config.get('REDIS_PORT', 6379),
        db=config.get('REDIS_DB', 0),
        password=config.get('REDIS_PASSWORD') or None,
        decode_responses=True,  # 自动 bytes → str
    )
```

### 读写流程

```python
def chat_stream(session_id: str, message: str):
    config = current_app.config
    prefix = config.get('REDIS_PREFIX', 'chat:session:')
    redis_key = f"{prefix}{session_id}"
    r = _get_redis()

    # 1. 读历史
    raw = r.get(redis_key)
    history = json.loads(raw) if raw else []

    # 2. 追加用户消息
    history.append({"role": "user", "content": message})

    # 3. 拼上 system prompt → 调 API
    full_messages = [system_msg, *history]
    response = client.chat.completions.create(messages=full_messages, ...)

    # 4. 流式返回，同时累积
    collected_content = ""
    for chunk in response:
        ...
        collected_content += content
        yield {"content": content, ...}

    # 5. 回复写回 Redis
    history.append({"role": "assistant", "content": collected_content})
    r.set(redis_key, json.dumps(history, ensure_ascii=False))
    r.expire(redis_key, config.get('REDIS_SESSION_EXPIRE', 604800))
```

### session_id 怎么来的

```python
req = chat_stream_request(**data)
session_id = req.session_id or uuid.uuid4().hex    # 没有就生成一个
```

第一次请求不带 `session_id` → 后端生成 → 放在 SSE 第一个消息里返回 → 前端存下来后续请求带上。

## 6. 验证

### 场景 1：多轮对话

```

        → 回复 "你好小红！"
        → 返回 session_id: "abc123"

请求 2: POST /api/chat/stream  {"message": "我叫什么名字？", "session_id": "abc123"}
        → 回复 "你叫小红"         ← AI 记得上轮内容
```

### 场景 2：重启后记忆不丢

```
停止 Python 进程 → 启动 Python 进程

请求 3: POST /api/chat/stream  {"message": "我刚才说了什么？", "session_id": "abc123"}
        → 回复 "你让我帮你分析"  ← 数据在 Redis 里，重启不影响
```

## 7. 小结

1. **对话记忆解决 AI"失忆"问题**——后端存历史→下次请求拼回去→AI 才能记住
2. **内存 dict 是最简单的实现**，但重启丢、不共享、不清理
3. **Redis 做了三件事**：持久化（重启不丢）、共享（多实例共用）、自动过期（TTL）
4. **Key 设计**为 `chat:session:{uuid}`，值存 JSON 数组，不含 system prompt
5. **Service 层封装存储细节**，Route 层完全不需要知道背后是 dict 还是 Redis
6. **读写流程**是固定的：读历史 → 追加用户消息 → 调模型 → 累积回复 → 写回 Redis
